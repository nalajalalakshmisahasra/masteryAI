# Database

The backend currently persists to a single JSON document store: `backend/data/craft_mastery_store.json` (path overridable via `STORE_DATA_DIR`). Private product images are stored under `backend/data/private-media/` (`MEDIA_STORAGE_DIR`) and are only served through authenticated `/api/files/:id` routes.

Supabase/SQL (`DATABASE_URL`) and Cloudinary (`CLOUDINARY_*`) are declared in configuration (see `.env.example` and `backend/server.ts` status endpoint) but are **not wired into the runtime yet**. This folder will hold formal schema definitions when that migration happens.

## Current store shape

```
craft_mastery_store.json
├── products:  CraftProduct[]        (seeded from backend/src/data/mockData.ts)
├── inquiries: ProductInquiry[]      (seeded ditto)
├── users:     StoredUser[]
├── files:     StoredFile[]
└── savedAt:   ISO timestamp
```

The TypeScript domain model lives in `backend/src/types.ts` (also used by the legacy web prototype):

### CraftProduct (key fields)

| Field | Type | Notes |
|---|---|---|
| `id` | `string` | `prod-…` |
| `artisanId` / `artisanPhone` / `artisanName` / `artisanLanguage` | `string` | ownership + contact + UI language |
| `title`, `shortDescription`, `fullDescription` | `string` | generated by `POST /api/ai/generate-description` |
| `category`, `material`, `craftTechnique`, `dimensions`, `weight`, `timeToMake`, `region` | `string` | extracted by `POST /api/ai/extract-info` |
| `originalImageUrl`, `enhancedImageUrl` | `string` | data URL or `/api/files/:id` reference |
| `suggestedPriceMin`, `suggestedPriceMax`, `recommendedPrice` | `number` | from `POST /api/ai/pricing-recommendation` |
| `finalPrice` | `number` | artisan-confirmed price |
| `pricingReason` | `string` | rationale shown to the artisan |
| `stockQuantity` | `number` | |
| `status` | `'DRAFT' \| 'PROCESSING' \| 'READY' \| 'PUBLISHED' \| 'SOLD_OUT'` | |
| `customizationAvailable` | `boolean` | |
| `translations` | `{ [lang]: { title, shortDescription, fullDescription } }` | optional, ≤13 languages |
| `createdAt` | `string` | ISO |

### ProductInquiry (key fields)

| Field | Type | Notes |
|---|---|---|
| `id` | `string` | `inq-…` |
| `productId`, `productTitle`, `productImage`, `productPrice` | | product snapshot |
| `customerId`, `customerName`, `customerPhone`, `customerLanguage` | | stripped from responses for non-admins |
| `artisanId`, `artisanName`, `artisanLanguage` | | |
| `requestedQuantity` | `number` | 1–10000 |
| `status` | `'PENDING' \| 'ACCEPTED' \| 'REJECTED' \| 'FULFILLED' \| 'IN_PROGRESS'` | |
| `messages` | `InquiryMessage[]` | each: sender, originalText/Lang, translatedText/targetLang, timestamp |
| `createdAt`, `updatedAt` | `string` | ISO |

### StoredFile

| Field | Type |
|---|---|
| `id` | UUID |
| `productId` | owning product |
| `ownerUid` | Firebase UID (access control) |
| `mimeType` | `image/jpeg \| image/png \| image/webp` |
| `size` | bytes (≤ 8 MB) |
| `storageKey` | file name inside the media dir |
| `createdAt` | ISO |

## Intended evolution

1. Formal SQL/Supabase schema definitions (DDL or migrations) will be added here when the `DATABASE_URL` integration is implemented.
2. Product media moves to Cloudinary once `CLOUDINARY_*` integration lands; `/api/files/:id` behavior must be preserved or migrated deliberately (see `docs/api-contract.md`).
3. Seed/demo data must stay separable from real user data (see `DEMO_DATA_ENABLED` / `EXPO_PUBLIC_DEMO_DATA` flags).
